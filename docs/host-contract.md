# TakeAgent host contract

The integration manifest is descriptive build metadata. It does not grant authorization or enable a live service. Production must keep `liveEnabled: false` until separately approved and verified. Import this library server-side only; it has no HTTP listener, network calls, credentials or persistence.

1. Authenticate and authorize a selected TakeAgent project using existing host services; apply billing/usage limits and revocation checks. Construct `context` with `tenantId`, `projectId`, selected project `currency` and server-calculated ISO `today`. Never accept this context from a report or browser as authorization.
2. Accept a user-selected UTF-8 CSV or values-only XLSX up to 2 MB. Apply upload limits before reading the request body. No automatic whole-workbook or folder ingestion. Keep raw files within host retention and deletion controls; do not log file content.
3. Choose a profile. For vendor-default Detail CSV column names, use `wrapbook-pas-cost-detail-csv-v1` (provisional; see `docs/profiles/wrapbook-pas-cost-detail-csv-v1.md`). For customized headers, use `wrapbook-pas-mapped-csv-v1` with `reviewedMapping` true only after the user reviews the mapping and report assumptions. `mapping` keys are `account`, `rowType`, the six cost fields and optionally `accountPath`; values are exact CSV header names. No header guessing or unselected columns.
4. Obtain source provenance in `options.metadata`: report identity (`sourceName`), revision, as-of date and reporting period/filter identity (`periodBasis`) plus project/tenant/currency. Explain and require cumulative actuals and `remaining-unpaid-only` commitment semantics. Set `options.completeForSelectedScope` to true only after confirming that the report is complete for the selected scope and that parent totals are removed from detail rows. Preserve full period/filter identity in periodBasis so different scopes cannot be compared. No source text is an instruction to the host or an AI.
5. Call `await previewFile(bytes, options, context)` (returns snapshot and review), or the format-specific preview function and show cost measures, warnings, hierarchy, source row/column mapping, source SHA-256 and source total row. Each input detail row is counted exactly once. An explicit final `total` row reconciles all six measures; intermediate subtotal rows are rejected. Slash-separated account paths must terminate in their leaf account. All amounts must use signed plain decimal notation with at most two places; localized numbers, currency symbols, formulas and missing amounts fail visibly.
6. `compare` is a pure read-only operation. It checks project/tenant/currency/period/source identity, requires a new revision for changed content and rejects older report dates. An unchanged snapshot ID means the host should avoid a duplicate write. The host must own transactional idempotency, version checks and authenticated retrieval of prior snapshots; do not trust caller-supplied fingerprints as storage authority.
7. Any future persistence or finance-plan change must have a separate explicit apply operation and concurrency guard. Do not modify original budgets, commitments, collateral or payment schedules based on a cost report alone. Reuse TakeAgent's existing finance-review services for financing interpretation after a separate reviewed integration.

## XLSX boundary

Mapped values-only XLSX parsing now runs in a bounded worker. Require exact worksheet and rectangular range; use profile `wrapbook-pas-mapped-xlsx-v1` and `format: xlsx`. See README for archive, cell, output, heap and timeout limits and rejected constructs. Text identifiers are mandatory; numeric codes are rejected. Original source cell references survive extraction. This is not a native Wrapbook layout profile and does not certify arbitrary exports. Keep upload/body/concurrency limits outside this library, and isolate untrusted parsing at the host process boundary. No production UI, retention or authorization is supplied.

Errors are intentionally short and exclude raw cell content. The host should show the error without echoing uploaded payroll/bank data. Synthetic tests cover library scope checks; production authentication, rate limits, storage, retention and UI behavior require host tests.

## Bounded host responses

Use `await previewFileForHost(bytes, options, trustedContext)` from the root exports for HTTP/UI previews. It validates and reconciles the complete report first, then returns at most 30 rows, findings and XLSX cell-provenance records (optional `{limit}` 1–100 as fourth argument). Full totals and identity are preserved; `totalRowCount`, `totalFindingCount`, `truncated` and `presentationOnly: true` explicitly describe the view. Serialized output cannot exceed 256,000 UTF-8 bytes; unusually large metadata fails visibly. `presentPreview(fullResult, {limit})` presents an already validated full result.

Keep the original full result for comparison/import logic; never pass truncated presentation rows to `compare` or persist them as a complete snapshot. `previewFile` remains the complete-data API. The host must still authenticate, remove private scope identifiers where appropriate and enforce request/concurrency limits.
